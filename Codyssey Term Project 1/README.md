### 주제 필터링 기준과 선택 이유

**수집 대상**

- TechCrunch RSS 피드에 등록된 최신 기술 뉴스를 수집 대상으로 설정하였다.
- 기사 제목과 RSS 원문 내용을 기준으로 AI, 소프트웨어, 모빌리티, 전기차, 플랫폼, 스타트업 및 투자 관련 기사를 선별한다.

**키워드 및 태그 목록**

- AI : 인공지능, 생성형 AI, AI 모델, AI 콘텐츠, 자동화
- 테크 : 소프트웨어, 플랫폼, 모빌리티, 로보택시, 자율주행, 전기차
- 스타트업 : 스타트업, 투자, 펀딩, 벤처캐피털, 인수
- 보안 : 사이버 보안, 데이터 보호, 보안 솔루션
- 기타 : 위 분류에 직접 포함되지 않지만 기술 산업 동향을 파악하는 데 필요한 기사

**선택 이유**

AI와 디지털 기술은 변화 속도가 빠르고 관련 뉴스가 지속적으로 생산되기 때문에 자동 수집과 요약의 효과를 확인하기에 적합하다. 또한 AI, 모빌리티, 플랫폼, 스타트업 투자 등 다양한 유형의 기사를 포함하면 자동화 시스템이 서로 다른 주제의 내용을 일관된 형식으로 요약하는지 검증할 수 있다. 기사 제목, 발행일, 원문 URL, AI 요약문을 함께 저장하여 사용자가 원문을 직접 확인할 수 있도록 구성하였다.

### 에러 처리 정책과 선택 이유

**1. 중복 기사 처리**

- 원문 URL을 기본 중복 확인 기준으로 사용한다.
- 원문 URL이 제공되지 않는 RSS 항목은 GUID를 보조 식별값으로 사용한다.
- 기존 데이터베이스에 동일한 원문 URL 또는 GUID가 있으면 새 페이지를 생성하지 않는다.

중복 기사가 반복 저장되면 같은 뉴스가 여러 번 요약되어 데이터베이스의 가독성이 떨어지고 AI 호출량도 불필요하게 증가하기 때문에 중복 검사를 먼저 수행하도록 설계하였다.

**2. AI 요약 실패 처리**

- AI 요약이 실패한 기사는 처리 상태를 `요약 실패`로 기록한다.
- 오류 메시지 속성에 실패 단계와 오류 원인을 저장한다.
- 일시적인 API 오류나 응답 지연은 `재시도 대기` 상태로 전환하여 이후 다시 처리할 수 있도록 한다.
- 하나의 기사에서 오류가 발생하더라도 나머지 기사 처리는 계속 진행한다.

오류가 발생한 기사를 바로 삭제하면 실패 원인을 추적하기 어렵기 때문에 처리 상태와 오류 메시지를 별도로 기록하도록 하였다. 또한 일시적인 오류로 수집 대상이 누락되는 것을 방지하기 위해 재시도 상태를 두었다.

**3. 필수 데이터 누락 처리**

- 원문 URL이 없을 경우 GUID를 이용해 중복 여부를 확인한다.
- 원문 URL과 GUID가 모두 없거나 기사 제목이 비어 있는 항목은 불완전한 데이터로 판단하여 저장하지 않는다.
- 정상적으로 처리된 기사만 `수집 완료` 상태로 관리한다.

필수 정보가 없는 기사를 저장하면 원문 확인과 중복 판별이 어려워지므로 최소한의 식별 정보가 확보된 기사만 데이터베이스에 저장하도록 기준을 설정하였다.
